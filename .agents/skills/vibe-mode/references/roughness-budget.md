# Roughness Budget

Acceptable when it does not invalidate the learning objective:

- representative fixture data;
- limited happy-path coverage;
- local/in-memory state;
- temporary copy/content;
- intentionally minimal error presentation;
- duplicated code that will be discarded or rewritten.

Not acceptable to hide:

- a known security boundary;
- an irreversible data side effect;
- behavior that makes the demo answer a different question;
- a broken primary path;
- production-readiness claims without production validation.
